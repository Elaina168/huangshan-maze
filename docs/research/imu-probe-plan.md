# IMU 四向映射预研实施记录

对应 C-11/C-18/C-19/C-24，支持后续 REQ-002/003/011；这是诊断预研，不实现迷宫功能，不确定正式校准/死区参数。

用户在已说明“四向映射预研”的下一步后要求继续。问题是屏幕朝向固定时，各姿态相对中立的加速度轴与符号如何变化。采用最小串口探针：msh命令 `imu_probe neutral|right|left|up|down`，每次40点、样本间等待50ms。姿态标签只是用户记录，不自动识别姿态。

数据路径：串口命令→msh线程→i2c3→ID核对→保存控制寄存器→启用104Hz/±2g加速度→有截止的就绪检查→读三轴→原始记录与统计→恢复配置→命令返回。只有此诊断命令访问IMU；不调用LVGL、不创建长期任务。底层I2C默认超时5000ms来自drv_i2c.c，200ms就绪期限不意味着阻塞I2C能被200ms中断。故障会结束取样并尝试恢复，保留采样和恢复两种错误。

文件：新增 `src/imu_probe.c` 为诊断命令，`tests/imu_probe/` 提供真实源码的主机故障注入，`scripts/test_imu_probe.py` 编译运行主机测试；project/proj.conf增加实际SDK的I2C3配置。main.c中的本人RGB修改保留。来源清单标记修改的配置，具体复用方法记入THIRD_PARTY。

## 下一轮：校准、死区与输入时效

用户已明确回复“按此设计继续”。新增现有msh诊断流程的命令`imu_control_probe`，沿用104Hz/±2g配置与50ms采样等待。关联REQ-002/003/011与TC-002/003/004/005/014的预研条件，不将诊断结果直接填写为产品用例通过。

数据路径：命令→核对ID并保存配置→20个连续有效样本的滑动窗口→校准参考→四向映射→逐轴死区→时效检查→5秒串口输入记录→恢复配置。窗口跨度至少950ms，XYZ每轴范围不超过300 raw；不稳定时滑动到下一窗口，校准逻辑预算3000ms，失败结束。参考只在本次命令校准成功后确定，不自动更新。每轴差值绝对值≤300时输出0，超出后扣除300；屏幕向右/向下为正，不换算速度或像素。

相邻取样开始时间的间隔或本次读取开始至消费检查的年龄超过100ms，记录`valid=0 xy=0,0`并结束；读取失败立即结束。第一条样本没有前一间隔，仍检查年龄。tick差值使用无符号减法处理回绕。时间戳是软件读取开始时间，不是传感器内部采样时间；真实板端调度与显示响应仍待测。

保存配置失败不写配置；写入、取样、校准或时效失败都尝试恢复已保存的两项寄存器，分别报告操作与恢复错误。3秒/5秒是命令的逻辑时间预算，SDK阻塞I2C及恢复调用可能延长墙钟总耗时；不修改共享总线或SDK超时。无LVGL、长期任务、滤波或速度曲线。main.c与原`imu_probe`保持现有行为。

验证：实际C源码主机注入覆盖稳定/持续晃动/晃动后稳定、四向、死区边界/极值、100/101ms年龄及间隔、tick回绕、读失败、配置失败和恢复失败；之后真实板型构建。真机先稳定中立，再分别重跑四向，最后持续晃动测试失败；100ms候选有效期还需观察实际日志，故障注入不冒充真实I/O验收。候选参数的离线依据另见[回算证据](../../evidence/imu/2026-10-10-parameter-replay/README.md)。

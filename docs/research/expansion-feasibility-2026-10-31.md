# 用户选定扩展范围：可行性与实施顺序

日期2026-10-31。依据用户最新清单、实际0.6.1源码、SDK v2.5.1和官方板卡资料；本轮为可行性研究，不实施新玩法。用户明确所列功能全部要做，未列功能不加入。本报告的技术建议不是已批准的详细玩法设计。

## 最新生效范围修订

用户随后表示没有喇叭/马达，音效、蜂鸣提示、振动先不做。保留RGB；不再以附件确认阻塞软件推进，也不再要求用户识别圆柱附件。

产品日常使用必须板上独立完成。电脑仍用于开发、烧录和必要验证，不作为产品功能的控制端或工具端；不新增电脑端地图生成/转换工具、串口操控依赖或联网排行。此前电脑端方案被本节与下方更新的顺序替代，原始核查证据保留。

## 1. 结论与证据

所选软件玩法具备实施条件；移动实体碰撞、黑暗显示与组合关卡需要重点预研，不承诺未经测量的机关数量或帧率。官方板卡支持RGB、音频输出和外接马达驱动；用户现按无喇叭/马达处理，相关功能暂停；XHXDZ-30B01身份仍未知，无需为了当前范围继续识别。

[原始证据与核查记录](../../evidence/research/2026-10-31-expansion-feasibility/README.md)。官方PDF第1/2/3页已实际查看；无可用原理图，因此不编造马达工作电压、喇叭阻抗或连接器规格。SDK/示例引脚不等于对附件电气参数的完整确认。

当前结构已将状态/校准、采样、物理、地图数据和UI分开。地图用maze_level_t和常量表描述，普通/冰面已有，启动固定冰岔迷宫；新功能是在此基础上增加，不重写整个工程。

| 看门狗 | SDK example/rt_device/wdt及BSP_USING_WDT，当前未启用 | 可做，最终使能前须确定健康判据、超时及存档/音频最长阻塞；不能只在独立线程无条件喂狗 |

当前生成配置AUDIO、PKG_USING_FLASHDB、BSP_USING_MOTOR、RT_USING_WDT/BSP_USING_WDT关闭。板表有DFU/BLE KV分区，但它们不是本游戏可随意占用的空间。当前只有devfs不代表FS_REGION已经挂载为可存档文件系统。优先评估SDK已有FlashDB/FAL路径，游戏中不频繁擦写Flash，分区和断电一致性需专门验证。

## 3. 全部选定功能

| 选定内容 | 当前基础与实现可行性 | 难度/主要依赖 |
|---|---|---|
| 门、钥匙、开关 | 可做；常量地图增加机关描述，本轮状态独立保存 | 中；门关闭时碰撞、拾取/开门一次性事件、重玩复位 |
| 移动障碍、巡逻块 | 可做；必须按物理时基更新运动和相对碰撞，不能只移动画面 | 高；防穿透、挤压规则、暂停冻结与恢复 |
| 闸门、定时激光 | 可做；激光为屏幕危险区，不需要外接激光器 | 中至高；开合时球在门内/危险区的规则需明确 |
| 不同地面替代加减速带 | 普通/冰面已有，可增加高阻力等材质 | 低至中；不同阻尼与视觉对应，不另加未选定的速度带道具 |
| 检查点复活 | 可做；改变原落坑结束本轮规则 | 中；复活位置/清速、时间、失误次数、钥匙/墙状态的保留策略 |
| 可破坏墙 | 可做；按本轮状态启停对应墙体碰撞与绘制 | 中；破坏触发方式需设计，不能默认撞墙就破坏 |
| 磁铁/吸附区 | 可做；虚拟区域向物理模型施力，无需真实磁铁 | 中；吸力上限、作用范围、可脱离性及墙体关系 |
| 黑暗关卡 | 可做；保留完整物理图，只限制可见区域 | 高；局部遮挡/刷新策略、提示可读性，避免默认巨大透明层和全图重绘 |
| 选关/下一关 | 可做；现有独立地图实例可扩展为关卡目录 | 中；触摸事件隔离、切关重置采样代次/时间/机关状态 |
| 解锁与进度 | 可做；关卡目录、完成标记及持久化 | 中；稳定关卡ID/数据版本，不能靠显示顺序识别旧存档 |
| 二维数组/字符串地图 | 可做；推荐“地面格子+独立对象表”，由板端装载为几何数据 | 中；一个字符无法同时表达地面、门、检查点等叠加对象，需分层描述 |
| 随机地图生成 | 可做；改为板端固定种子生成并检查候选，先限定格子数和机关模板 | 中至高；在选关/准备状态生成，限制耗时/内存，禁止把随机打点当可玩地图 |
| 地图合法性检查 | 已有当前图专项拓扑/安全路径/惯性测试，可推广通用工具 | 中至高；边界、球半径、起终点、机关引用、钥匙前置、检查点安全位置与动态路线 |
| 失误次数 | 可做；在一次真实落坑/危险结算时增加 | 低；设备错误不算玩家失误，复活与重玩边界需明确 |
| 排行榜/成绩 | 可做；本地、分关保存时间和失误记录 | 中；排序与检查点/反向模式分类需设计，避免不可比记录混排；不扩展联网排行 |
| RGB灯效 | 有现成硬件与驱动，可做 | 中；事件驱动/非阻塞，不延误采样和UI |
| 蜂鸣提示/音效 | 接口支持，但用户已暂停 | 本轮及后续当前范围不实施 |
| 振动反馈 | 驱动路径存在，但用户已暂停 | 本轮及后续当前范围不实施 |
| 过关动画/失败闪烁/菜单过渡 | 可做，已有LVGL绘制和动画支持 | 中；停止/取消正确，避免动画阻塞主循环 |
| 方向反转配置 | 可做；在控制输入映射层变换，不改变IMU驱动 | 低；清晰标识模式并区分成绩，避免被误认成轴映射错误 |
| 参数集中 | 当前物理/校准参数分别在两个头文件，可集中公共可调参数 | 低；配置只做实际需要的范围，不建立推测性框架 |
| 看门狗 | 有SDK支持，尚未启用 | 中；依据主循环/采样真实健康状态喂狗，超时恢复需实际短测 |
| 成绩/解锁进度掉电保存 | 硬件/SDK支持 | 中；专用分区、版本/校验、掉电中断保持至少一份有效记录，明确烧录是否保留存档 |

静态BFS连通不等于带钥匙/定时门/磁力的真实可通关；合法性分三层：数据约束和球半径几何→带机关状态的路线检查→真实物理轨迹/板端关卡体验。随机图先限机关组合，再逐步增加受支持模板，不能承诺任意组合自动保证可玩。

## 4. 推荐顺序（按最新范围，音效/振动暂停）

0. 保留分区/存档/看门狗接口核查；取消附件确认与声音/振动预研，不恢复旧B/C。
1. 参数与地图基础：公共参数、稳定关卡ID、二维数组/字符串+对象表、板端装载与静态合法性检查；已有地图回归不变。
2. 多关卡闭环：中文选关、下一关、重玩/返回，先用基础图验证切换；方向反转配置与模式标识在此加入。
3. 进度与数据：解锁、失误次数、成绩、本地分关排行榜，以及专用分区的掉电保存；定义后续机关所需的复活/模式成绩字段，稳定数据版本。
4. 第一批机关：不同地面、钥匙/开关/门、可破坏墙、检查点复活；根据机制逐关验证和更新成绩规则。
5. 第二批机关：磁力/吸附、闸门/激光、移动/巡逻实体；先固定模板，重点解决暂停/复活后状态及碰撞。
6. 板端随机生成：在准备/选关阶段按受支持模板与种子生成；板上做数据、球半径几何与受限机关状态可达性检查。生成工作设置预算并保持UI响应，无法生成时明确提示重新生成。任意复杂机关组合的自动求解不作无依据承诺；必要真实模型自动测试仍是开发验证，不成为玩家使用步骤。
7. 黑暗与反馈：黑暗可见区域、过关/失败/菜单动画、板载RGB，不加入声音/振动；效果统一消费游戏事件，不复制规则，不阻塞UI/采样。
8. 看门狗最终接入及相关回归：以加入存档/生成/动画后的真实最大工作时间确定监控；前面预研接口，最后正式开启，不掩盖原始故障。每阶段完成必要相关验证，未执行保留证据缺口。

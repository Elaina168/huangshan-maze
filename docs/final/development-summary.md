# 黄山派体感迷宫研制总结

李天宇　2024211450　单人项目　2026-11-07

## 目标与最终成果

项目从课程RGB/串口例程出发，在黄山派上实现离线体感迷宫。以倾斜输入、钢珠惯性、墙/陷阱/终点和触摸状态机组成基本闭环，逐步增加滚动大地图、三种地面、关卡与存档、基础/动态机关、板端随机地图、黑暗/反转玩法、视觉/RGB反馈和看门狗。最后按实际使用意见精简界面，项目最终确定为0.16.1-ui-trim。

最终保留冰环迷宫、机关试炼、动力机关三固定关和随机娱乐。固定关按四玩法统一排名，每关只存屏幕完整显示的前5条；随机不计成绩。硬件使用板卡、屏幕、触摸、IMU、Flash和USB供电，采用板端独立运行方式。

## 研发过程

早期先核对课程要求、实际SDK版本及外设资源，记录中文路径构建、串口占用、烧录工具和SDK激活等问题。建立ASCII临时快照构建与哈希核对，避免路径问题和源码/固件不一致。

随后通过不同姿态采样确认轴向、噪声和校准候选参数；完成显示触摸、资源和后台采样预研，再实现输入时效、校准/暂停/胜负/错误状态与基础物理。在体验测试中发现放平立刻停球不自然后，改为加速度、阻力和速度累积，并按冰面/粗糙地面区分手感。

扩展阶段按八阶段实施路线推进。地图从硬编码几何转为可描述/检查的数据；关卡、存储、机关、动态危险和随机生成逐步接入。关卡迭代后将目录收敛为三固定关与随机娱乐，代码和档案迁移同步调整。

最后解决刷新卡顿、闪球/黑块、成绩返回和RGB节流问题，加入局部黑暗、统一真实前5榜与主循环看门狗。最终界面删除USB说明、部分游玩统计和累计失误，并移除对应无用展示代码及5个字形。

## 关键技术取舍与收获

- 把传感器、纯逻辑和UI分开，使碰撞/状态/机关可以在主机确定性验证；由主线程统一管理LVGL对象。
- 输入有序号、代次和时间，退出和切关按会话代次匹配采样结果；故障通过错误页和重试流程处理。
- 显示是异步消费者。球闪烁和残留问题需要核对实际提交完成与缓冲所有权，刷新诊断同时检查渲染耗时和实际传输完成状态。
- 存档按稳定关卡ID迁移，用A/B副本和明确错误保留已有数据；受控进程中断提供可重复库级验证，用于检查事务提交过程和副本恢复。
- 看门狗必须监视真实工作进展。SDK idle自动喂狗会掩盖主循环阻塞，因此应用接管，在完整轮次末尾喂狗。
- 功能设计围绕板端体验持续调整。随机娱乐、统一前5和界面精简使操作流程更集中。

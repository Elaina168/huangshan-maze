# 第8阶段：看门狗与整合

用户授权进入下一阶段，并要求灯效默认开启、删除独立按钮。按既定第8阶段范围执行，不新增玩法、音效、马达或电脑依赖。

## 需求与成功标准

- REQ-059 / TC-082：实际SDK硬件WDT启动30秒窗口；main取得所有权时删除SDK idle喂狗hook。完成初始UI/存档后切换5秒运行窗口，仅完整一轮UI/输入/导航/生成或存储/渲染/RGB结束才能喂狗，每250ms最多一次。flush服务、空闲线程和定时器不得代喂。超5秒的完成间隔锁存失败，不再喂狗。所有设备调用失败记录并快速失败。
- REQ-060 / TC-083：WDT超时使用SDK弱回调转HAL_PMU_Reboot，避免默认二段50秒等待；回调不写Flash/日志/调用LVGL。重启按原流程读A/B档、回菜单，不恢复旧速度或校准，不自动提交新成绩。原100ms输入/物理保护继续；被识别的采样错误页仍是活的UI，允许喂狗和人工重试，不能用持续重启代替错误页。
- REQ-061 / TC-084：RGB默认开，无独立设置按钮；内部lighting只作运行故障锁存，日志及选关非交互状态提示错误；重新启动可重试。普通游戏仍熄灯，菜单低亮呼吸及机关/胜败短反馈不变。
- TC-085：新版真实板端短测，包括正常游玩/随机生成/保存重启、RGB、菜单限定故障注入与恢复。主机模拟不能证明实物复位时延。

## SDK证据及取舍

v2.5.1 `customer/boards/Kconfig_drv` 的BSP_USING_WDT选择RT_USING_WDT；watchdog.c启动注册wdt并安装idle hook。main通过rt_hw_watchdog_hook(0)删除该hook；沿用已打开设备，GET_STATUS要求1。驱动SET_TIMEOUT内部未透传HAL错误，因此设备接口返回0仅证明请求被接受，真实启用与超时复位须板端确认。驱动IRQ会先重配，再调用wdt_store_exception_information；本工程强实现该弱符号，使用实际bf0_hal_pmu.h/HAL_PMU_Reboot，保留芯片复位路径。SDK和系统中断完全卡死时软件回调不执行，仍依赖硬件二段复位，不能承诺5秒内完成所有故障复位。

应用不新增独立监控线程：完整主循环是健康凭证，阻塞显示完成即使持续调用flush也不能喂狗；IMU超时已由既有错误状态隔离，不因错误页重启。启动采用30秒窗口涵盖UI/档案初始化，运行5秒允许菜单地图合法性检查和FlashDB同步操作；这是候选上限，保留实际耗时日志，板端验证后才确认裕量。不延长既有100ms保护，也不按page豁免无限阻塞。

串口`maze_watchdog_test confirm`仅请求一次注入，由main在选关页消费并延迟15秒；其他页面拒绝。仅用户手动执行，软件验证不自动操作板子。重启后请求是BSS清零，不形成重启循环。不在断电存档中记录测试标记。

存档v7、三固定关+随机娱乐、排行榜五条、分区和单帧缓冲保持。复位只会恢复最近已保存的结果；未保存进度可丢失，不写伪造成绩。

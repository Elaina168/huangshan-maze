# 三关正式版：滚动地图与旧存档升级设计

## 目标、范围与方案

用户选择保留冰岔、冰弯两关，新增已确认的[冰环迷宫](2026-11-02-ice-loops-layout.md)。默认正式构建提供三关、跟随镜头、独立成绩与共享解锁，升级保留旧档；产品仅依赖板子和供电。建议正式版本名0.10.0-three-levels，具体版本名是工程建议。

已选方案为独立第三关。改造第二关会影响既有成绩可比性，已不采用。存储建议继续A/B完整快照并扩展格式：相对拆成多个独立key，它延续既有原子结算和中断恢复边界，不引入跨key提交协议。后者只是工程上比较过的替代方案，不表示用户此前另行批准过任何存储格式。

本轮不增加新地面、钥匙/门/开关、可破坏墙、检查点、随机生成、声音、震动、RGB反馈、黑暗或看门狗。不改运动参数/陷阱判据，不清档、不伪造成绩，不把试验图加入正式目录。

## 地图与游戏规则

- 顺序及稳定ID固定为冰岔/frost_fork、冰弯/ice_bends、冰环/ice_loops。原两关数据、物理参数、模式及成绩口径保持。
- 第三关严格采用已确认JSON：700×600、14×12格、141段墙、6冰格、5坑、21处分岔、18条死路、2回环。普通/冰面参考路径及五个必经通道坑保持，不重新搜索或悄悄改几何。
- 初始仅开放第一关。任一模式通关第二关，为正常/反转共享解锁第三关；第三关各模式成绩独立，最后一关胜利显示全部完成，没有越界下一关。
- 挑战时间、失误、失败重试累计、暂停重玩和退出口径沿用REQ-033至036，不加入检查点语义。

## 界面、镜头与时序

选关页三入口采用固定纵向布局：标题/说明在24/56px附近，存档反馈保留84px一行；三个关卡行位于112/170/228px，各50px高；成绩行292px、方向行342px，底部391px保留保存按钮或提示。按钮尺寸遵循现有38px内容高度，不缩小为难以触摸的小入口。锁关可见且禁用。成绩页按目录依次循环三关，正常/反转切换不变，不能再使用当前`1-score_index`的两关切换。

游戏页沿用地图20,80处的350×300固定视口，HUD及按钮不动。统一world容器与固定提示层：前两关镜头偏移恒为0，第三关沿用140×120中央区、平滑系数12/s、边界夹紧和整球可见余量。开始/重玩/切关定位，暂停/错误/结果冻结，恢复不补停顿。不显示设计答案线、起始视口虚线或额外小地图。

正式UI复用0.9.3的234000B、64B对齐单份部分绘图缓冲，以及旧/新球屏幕区域合并。只有350×300视口级绘图数据，不创建700×600整图像素缓存；SDK旧小缓冲仍保留，不改SDK。较大单块可能降低app服务频率，必须重新测真实物理间隔。

将试验的条带提交回调服务推广至正式导航：在同一UI线程、SDK实际LV_EVENT_FLUSH_FINISH（flush_cb返回后，而非DMA物理完成）服务最新IMU快照、导航/app更新及采样请求；不调用LVGL、消费触摸或执行Flash写入。先让出1tick供优先级较低的IMU生产者运行。结果观察仍须幂等，回调与外层主循环不能重复计时、失误、排名或解锁；写档只由外层安全状态处理。

场景对象一帧内保持快照，即使app在服务中进入终态，也到外层再更新显示。旧点击按page/version/state/generation过滤；切关先停止请求、删除旧场景，再装载/绑定，新代次单调递增。格式/几何/通路错误仍进地图错误页，不能继续读旧map。

## 存档格式与解锁迁移

以下为本轮拟定格式决策，用户此前只批准过两关v1；需随本设计确认。

| 项目 | 旧v1（继续支持读取） | 新v2（唯一写入格式） |
|---|---|---|
| magic | HMZ1 | HMZ1，保持格式家族标识 |
| format u16 | 1 | 2 |
| length u16 | 353 | 517 |
| revision u64 | 原值 | 正常递增 |
| rules u32 | 1 | 1，旧关计分规则不变 |
| level_count u8 | 2 | 3 |
| 每关记录 | 164B | 164B，字段及正常/反转前5记录不变 |
| 末尾 | IEEE CRC32 | IEEE CRC32 |

长度来自当前真实编码：21B头+每关164B+4B CRC。v2固定顺序输出三个稳定ID；解码按稳定ID归位并拒绝重复/缺失/未知ID、错长度/CRC/计分规则/计数等外部格式错误。不得读取未初始化尾字节或把517B读取缓冲当作实际blob长度。

v1解码到三关RAM：保留原两关所有字段（包括排序/同分先后、累计失误、完成位、解锁、各模式及存储修订号），第三关无历史成绩/失误；只有原第二关completed中任一模式已完成才开放第三关。仅已解锁第二关不算通关。不会把前期试验反馈或模型路线转换成通关记录。

打开两份数据库仍先只读探测。两份支持的有效格式按revision选最高，不能让格式版本替代修订号排序；同revision时，两份都解码归位并编码为规范v2字节再比对：一致视作同一快照，不一致明确冲突，不因旧新字节长度不同误判，也不静默覆盖第三关数据。

只要任一副本识别为未知格式/规则版本，仍明确报错并禁止写擦；不因另一份已知档可读就覆盖未知数据。已知格式损坏且另一份有效时沿用非当前副本修复规则。两份全空才新建默认v2；首次建库中断仍沿用既有明确错误边界。

## 迁移事务、失败和回退

1. 选出的最高有效副本若为v1，读取及RAM扩展成功后标记本次需要迁移；store保存“已提交修订号”和源格式，不把RAM默认第三关误作已落盘。
2. 只在本次启动/打开成功时，把RAM档案revision提升一次，以标识格式迁移这一持久变化。显示正在保存，在接受选关操作前于安全菜单完成一次自动迁移尝试。初次只读打开本身不改源bank。
3. 目标是非当前副本：写入完整v2、读回并核对后才切active。源v1不写擦。迁移失败保留RAM扩展和原有效副本，显示未保存/重试；可以继续RAM游玩，不重复迁移递增或重复结算，断电可能回到旧已保存进度。
4. 手动保存重试使用同一待保存修订号；若写入实际完成但读回失败，重试仍需读回验证，不重新追加业务分数。重启未完成迁移时，再从旧v1扩展并尝试相同下一修订号，不能因重启叠加失误或成绩。
5. 迁移中断的恢复结果：完整旧v1可再次扩展，或完整新v2；不能读半份三关数据。两种有效格式交替存在是正常中间状态，不主动重写仍有效的另一份旧档，仅随下次实际保存轮换。
6. 达到无法递增的revision外部边界时明确返回存档错误，不回绕为0或清空档案。

**降级限制必须告知：**一旦新v2成功保存，旧0.9.0正式固件因不认识格式2会显示存档不可用，不能承诺降级后仍可查看旧成绩；它不会被授权清档。已有0.9.3独立试验固件不读写档案，仍可用于显示回退试验，但不提供正式成绩功能。无需电脑迁移工具、手动擦除或云端备份。

## 存储与资源约束

沿用A/B各32KiB、8KiB擦除块、原maze_flash代理逐bank写闸门及物理区域0x12DB0000至0x12DC0000。原分区和三文件烧录地址不变，无存档下载镜像。旧格式的“not_formatable仍可能恢复写入”问题不重犯，探测时底层仍强制只读。

正式地图容量提升到14×12，校验工作区仍静态36256B、uint16_t可容纳17061节点。第三关静态检查使用已验证保守BFS，不把几何连通证明写成玩家一定可通关。载入前先显示固定加载反馈，完成或失败后才恢复相关操作；装载耗时单独记录。实际交互/加载测量若不满足确认的准出条件，须定位瓶颈或分批推进，不能靠调大输入阈值掩盖CPU阻塞。

当前0.9.3未分配SRAM尾区119092B不是实际堆。设计预研把141墙数据输入现有真实LVGL，主机报告峰值43712B、暂停时free=13776B，能创建准备/校准/游玩/暂停/胜利/错误页，见[内存预研](../../../evidence/design/2026-11-02-ice-loops-01/ui-memory.log)。这支持先复用持久场景+LVGL裁剪，暂不引入对象池；不证明板端加入store及新字体后的资源已通过。

正式集成后必须核对新ELF静态尾区、main栈预算（当前8192B，存档读取双图像/解码临时变量不得放入大数组导致溢出）、UI峰值、档案库运行分配及一轮实际free/ps。不能把主机堆或119092B写作板端可用内存。若实测不够，本阶段不准出，按实际对象/缓冲瓶颈调整并回归。

## 模块边界

- 地图/目录：新增独立固定第三关定义，保留现有两份地图几何；布局JSON及C结果逐项对照。
- UI/镜头：统一正式视口/场景及服务注册，保持UI线程唯一；三关选关/成绩/最后关边界。
- 导航/进度：三关ID与共享解锁、模式独立、旧会话隔离、结果幂等；不依赖试验ID进行结算。
- 归档：v1/v2边界解码、v2规范输出及旧档RAM扩展，不操作Flash。
- store：实际长度/源格式识别、候选选择/同revision语义核对、A/B提交及迁移状态，不渲染UI。
- 主入口：菜单阶段的一次迁移、纯业务服务回调、外层安全存储与诊断；不从显示回调调用Flash。

## 方案比较与建议

1. 直接启用SDK内置SourceHanSansSC 16 CJK：已有配置和授权，但实际字形表缺少冰、迷、宫、暂等本次必需字，不能满足完整显示。
2. 推荐：从SDK现有完整NotoSansSC-Regular.ttf生成本界面专用16像素、4bpp静态字形，ASCII沿用已有Montserrat 16。只把所需字形及必要描述编入固件，不导入10MB原始TTF。用已有Pillow 12.3.0离线生成，不安装转换器/运行时字体引擎。生成文件用项目名称，保留字体原始版权/OFL、来源SHA与修改说明，记录到THIRD_PARTY.md。后续新增文案须重建字形。
3. 完整TTF及运行时字体引擎：可支持任意文字，但资源和工程改动更大，本轮固定文案无需引入。

用户回复“可以”，确认推荐的离线界面字形子集方案；由Codex在本会话实施，不再次要求执行方式确认。

## 字体证据

来源：SiFli SDK v2.5.1 external/lvgl_v9/tests/src/test_files/fonts/noto/NotoSansSC-Regular.ttf，旁有OFL.txt/README.txt。原始TTF为10560380 B，SHA256 ae82f4e2a55e1316a55bcc1d05e9555ce08d8bda07e893b486896b626fd852ff。只读解析源TTF Unicode cmap确认96个候选汉字均指向非零glyph；SDK内置位图覆盖检查发现多字缺失。

96汉字若按16×16、4bpp整格估算，像素约12KiB，另有字形描述、映射及最终文案标点；这不是最终固件增量，需实际构建测量。沿用16像素是Codex选择，目的是保留当前布局及刷新边界。

- FROST FORK → 冰岔迷宫；Start → 开始；Pause → 暂停；Resume → 继续。
- Calibrate → 校准；Replay → 重玩；Exit → 退出；Cancel → 取消；Retry → 重试；Back → 返回。
- 准备页：准备就绪 | USB在右侧。说明：轻倾加速，反向制动 / 红色陷阱请绕行 / 蓝色冰面更滑 / 到达绿色终点获胜。

- 暂停：已暂停。校准失败时保留本轮并显示原错误码；不把失败翻译成校准成功。

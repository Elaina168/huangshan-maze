# 第5阶段复杂机关与第五关设计

2026-11-03。状态：用户已确认设计及计划，软件与正式构建完成，板端待TC-070。用户已确认新增第五关、保留前四关的方向；下列数值与细节为Codex提案，不虚称已逐项确认。提交推送仍仅按用户明确指令执行，不自动烧录。

## 目标与方案取舍

按既定顺序实现磁力/吸附、定时激光/闸门、移动障碍/巡逻块，组成正式第五关“动力机关”。采用新增关卡方案：不改前四关布局、物理和原成绩；直接改第四关会影响旧榜可比性，独立试玩场则不能覆盖选关、解锁、成绩和存档闭环，均不采用。

本阶段不做随机地图、黑暗、动画灯效、看门狗、声音/振动、传送门或弹跳板。产品在板上独立操作，电脑只用于开发、烧录与验证。

## 玩家规则

### 磁力与吸附

固定磁心、有限圆形作用区。区内给钢珠指向磁心的加速度，随距离线性衰减，到边缘为零；磁心附近使用连续线性力避免方向奇点。候选外半径70像素、内半径12像素、峰值加速度240像素/秒²；到磁心距离r<=12时大小为240×r/12，12<r<70时为240×(70-r)/58，r>=70时为0，方向均指向磁心，r=0为零向量。玩家满幅输入加速度仍为600，能主动脱离；原总限速180保持。磁力叠加输入后再执行原地面阻尼，不传送、不直接改位置或强制清速。多个作用区相交时合力限幅240，防止无意增强。无倾斜输入时，磁力仍可使球起动，不能被原静止阈值吞掉。

吸附以相同磁心规则表现为靠近中心并逐渐稳定，不新增不可逃离的锁定状态。地图中用不同地面色与磁心标志显示作用范围，便于预判。

### 定时激光

固定水平/竖直线段，关闭1800ms、预警600ms、开启1200ms，周期3600ms，各对象允许固定初相位。关闭可通过；预警可通过并明显变色；开启时钢珠圆形边界接触有效激光即失败，失误与陷阱同样只记一次。开启瞬间若已接触也失败，不只检查本步终点。高速穿过用扫掠判定，不能跳过细线。

### 定时闸门

固定矩形门，候选开启2400ms、关闭前预警600ms、关闭1800ms，周期4800ms。开启/预警可通，关闭时像普通墙阻挡，不因撞门直接失败。关闭瞬间若球体与门重叠，则该门保持待关闭且继续显示预警；球体完全离开后才关闭。该等待只影响本次关闭窗口，下次周期按统一机关时钟继续。拒绝把球嵌进门内或瞬移到另一侧。

### 移动障碍与巡逻块

先做同一种实体：轴向直线往返的矩形块，端点短暂停留，用不同路径配置表现巡逻。候选速度35像素/秒、端点停留400ms，无旋转、曲线或追踪。碰撞按球与障碍的相对运动计算，静止钢珠也能被移动块推开；不能只比较两个最终位置。块碰球时沿接触法线推开/调整球速，切向惯性保留，不额外弹射。若被推向固定墙且已无足够空间，则失败一次，明确显示“被机关挤压”，复用失误/复活流程。路径端点及整个扫掠范围不得穿普通墙、门、其他巡逻路径、起点或检查点安全区。

## 时钟、暂停与复活

机关使用模型内部有效游玩时钟，沿用10ms物理步推进；不读取UI帧数、墙上时钟或I/O tick。事件发生在步内时按最早危险/接触时间处理；在激光相变、障碍折返点等时间边界切分当前步。不能把整步结束的机关状态用于整个运动段。同一时刻激光/陷阱/挤压失败优先于检查点、物品及终点；巡逻块推动球的位移同样经过危险区域和触发物扫掠，不以单独改位置绕过判定。

准备、校准、暂停、设备错误、胜败期间，机关位置和周期均冻结；继续后从原相位推进，不补暂停时长。重玩所有机关从固定初相位重新开始。检查点同时保存激活时的机关时钟、各闸门待关闭运行标志及原基础机关掩码；复活恢复机关快照与该时钟，再校准、清速继续，挑战累计用时及失误照旧保留。检查点必须设在全部动态扫掠范围之外，避免复活即受击。重校准及设备错误恢复保留当前相位。

## 第五关与地图检查

暂定稳定ID为dynamic_trial，显示名“动力机关”，新增在第四关之后；通关第四关任一模式解锁第五。旧四关的地图对象、物理参数与稳定ID不改。

新图沿用不超过700×600的世界范围和现有跟随视口。以多个转弯和分岔串联磁力区、激光等待区、闸门、巡逻区；保留安全等候区和检查点，陷阱位于必经通道但留整球可绕空间，不放到仅死路才遇到的位置。机关不能全部放到无关支路。具体几何在实现前生成可审阅全图预览，布局未确定前不声称已具可玩路线。

地图定义追加专用动态对象表，保留原基础机关表及旧图零动态对象路径。每类数量和总容量集中在maze_config.h，候选总上限8个；结构/名称在实施计划中明确，不复用基础机关link承载不相关参数。

装载时检查外部地图数据的数值、数量、周期、初相位、几何和引用；静态路径检查可把激光/闸门开放、巡逻运动区域单独标注，但只能证明开放几何连通。正式第五图还必须用真实模型输入轨迹覆盖等候、跨越、受力、碰撞及通关；不能宣称静态BFS已经证明动态关卡可解。

## 模块与显示

level/map持有只读定义；model负责磁力、统一机关时钟、相对扫掠和失败原因；app维持代次、校准及暂停语义；progress维持一次结算；UI只读模型状态绘制。仅UI线程操作LVGL。

动态块刷新合并旧/新区；激光/门只在可见状态变化时更新。保留当前显示完成等待和缓冲所有权约束；镜头滚动仍使用固定视口，不新增整图缓冲。机关与球的画面使用同一模型快照，避免逐对象读取产生错帧。原100ms输入/时基限制不放宽，不以卡顿掩盖性能问题。

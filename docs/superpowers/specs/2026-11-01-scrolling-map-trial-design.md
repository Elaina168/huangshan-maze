# 大地图与跟随镜头试验设计

日期：2026-11-01。状态：用户已确认设计并批准实施计划；本文件不是实测结果。

## 目的与范围

用户希望地图大于屏幕，只显示小球周围区域，镜头随小球移动。本轮先验证板端可玩性与显示性能，再决定正式机关关的地图规模。保留现有两关、运动参数与存档；第4阶段地面和机关暂后移，不增加本轮范围。

## 方案与取舍

采用固定视口、世界坐标与镜头偏移分离。另一方案为缩小整张地图，会缩小球和通道，不能实现用户所需的局部视野；整幅大位图再移动则增加缓冲和绘制成本，本轮不采用。

建议先做独立试验构建，不扩充正式关卡目录、解锁或排行榜。这样先验证镜头，再处理新关和存档兼容；试验版仍通过板上触摸开始、暂停、重玩，无串口操作依赖。正式版默认构建保持原行为。

## 试验行为（以下数值为建议起点）

- 地图14×12格，每格50像素，总尺寸700×600；屏幕视口350×300，位置沿用当前地图区域。球半径、墙厚、加速度、限速和阻尼保持原值，不缩放地图。
- 地图具有横向、纵向与折返路径，包含普通和冰面、可绕行陷阱及终点；验证布局即可，不作为第三张正式关卡。
- 小球进入视口中央区域之外时推动镜头；中央区域初始为140×120像素。镜头平滑追随目标，参数集中，按实际经过时间推进，不按绘制次数累加。具体跟随系数由实现测试确定并记录。
- 镜头限制在地图边界，绝不显示地图外空白；小球在边缘处可以离开屏幕中心。起始与重玩直接定位镜头，暂停冻结，继续不补算暂停时间。
- 碰撞、陷阱、终点与物理继续使用世界坐标；镜头只改变显示位置。标题、计时、触摸按钮和状态提示固定在屏幕上，提示面板属于视口而非世界。
- 只显示与视口相交的场景内容，活动更新不重建整页；不创建700×600整图像素缓冲。具体LVGL对象裁剪或复用策略在读取实际接口并测量后确定。
- 试验不打开或写入游戏档案，不结算正式排行、累计失误或解锁。刷回正式版仍可使用原存档。

## 成功标准与验收建议

正式实施前在需求和验收文件登记REQ-037、TC-050至TC-052；以下仅为拟议规则，未宣称通过。

1. TC-050：纯逻辑验证镜头死区、四边夹紧、起始/重玩/暂停/继续；同一世界输入下，启用镜头与关闭镜头的物理轨迹和胜败一致。
2. TC-051：真实LVGL离屏验证视口裁剪、滚动前后世界到屏幕转换、固定HUD、提示面板和切页对象生命周期；记录滚动刷新像素与内存。旧版局部刷新预算不能直接作为整片视口移动的通过依据。
3. TC-052：完整SDK构建后，用户一次板端短测覆盖横向、纵向、折返、地图边缘、暂停继续、重玩及终点。记录实际显示/主循环耗时与采样健康；保持100ms既有限值，不通过放宽阈值掩盖滚动阻塞。报告卡顿、球是否出视野与操作舒适度。

地图上限翻倍使5像素检查格点增至141×121=17061，当前uint16_t节点索引仍可容纳；队列加位图约36255字节（不含对齐），相较当前约9204字节明显增加。装载耗时、墙碰撞遍历和静态RAM需要单列测量，不凭容量推算宣布板端通过。

## 边界

这是可回退试验，不承诺本轮形成正式新关、最终镜头参数或正式资源验收。不加入小地图、缩放、手动拖动镜头、黑暗效果、机关或新的持久化字段。布局合法性仍是保守静态检查，不等于证明真实惯性下可通关。

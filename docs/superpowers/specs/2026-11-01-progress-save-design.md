# 第3阶段：成绩、解锁与板端存档设计

状态：用户已认可本阶段基本规则及“用时优先，同用时再比较失误”，随后回复“确认”，批准本具体设计。以下进入实施计划；尚未修改产品代码、配置或Flash，存储恢复预研未执行。

## 已确认的目标

- 新存档只开放第一关；正常或反转任一模式通关，都解锁下一关。
- 每次落坑计1次失误，校准失败及设备错误不计。本关重试继续累计，通关或返回选关结束本次统计。
- 每关前5条本地通关记录，正常/反转分开，用时优先，同用时再比较失误。
- 断电保存解锁、累计失误及排行榜，不保存正在游玩的坐标、速度或校准姿态。产品独立在板上使用，不联网、不依赖电脑操作。

## 方案与取舍

建议复用本SDK已有FlashDB KVDB/FAL，将64KiB专用空间分为两个32KiB独立数据库。每个数据库只保存一个完整档案blob，更新时写入另一份；不把成绩、失误与解锁分别写入而形成半份进度。项目显式声明独立区域，首次使用已有库，不安装或修改SDK。

另一方案为直接使用FAL维护双份原始记录，可减少库功能，但需要自写擦除、提交标记、掉电恢复及磨损轮换。本阶段已有FlashDB，建议利用库处理各副本内部记录和回收；跨数据库交替保存仅负责保留完整上一份。具体选择仍随本设计审阅确认，不能把“支持恢复”的库描述当作实测保证。

## 统计口径

一次“挑战”从本关首次点击开始延续到通关或返回选关。失败后的重玩、暂停页重玩均属于本次挑战；通关后的重玩、退出再选、进入下一关开启新挑战。准备页未开始不计时、不记挑战结果。

为防止反复重玩只保留最后一次的短用时，建议排行榜使用本次挑战各轮有效游玩时间之和；失败轮次及主动重玩的已游玩时间都保留，校准、暂停、设备错误等待及结果页面等待不计时。界面显示“挑战用时”和“本次失误”，底层原app每轮物理计时仍可重置，由成绩模块累计，不改变物理时基。

排行榜按显示精度的整数百分之一秒排序，先用时升序，再失误升序；两项相同则保留较早记录在前。相同分数的不同通关记录允许并存。列表只显示名次、用时、失误及模式，不加账号、姓名或未经核对的日期。

先累计完整游玩时长，再统一转换为百分之一秒，不能逐轮截断。成绩及累计失误归属挑战开始时固定的关卡ID/模式；分模式完成标记独立，共享解锁由任一模式成功推进。

每次LOST只记1次本次失误，并给该关该模式的累计失误加1。WON、LOST结算和重玩时间归并必须幂等：旧页面刷新、重试保存、迟到采样不能重复结算；不能仅用IMU generation标识一次玩家尝试，因为设备恢复校准也会改变generation。结果结算后无采样继续增长。

退出未通关挑战不进排行榜，已发生的累计失误仍保留。当前阶段尚无检查点；检查点计时/复活及可比性在第4阶段单独设计，不提前加入。

## 解锁与界面

解锁进度按稳定关卡ID记录，不能用当前数组位置持久化。初始冰岔开放、冰弯锁定；第一关任一模式通关后冰弯对两种模式开放。末关成功不访问不存在的下一项。

选关页保留关卡与方向入口，锁定关卡可见且标注未解锁，点击不能加载。新增“成绩”入口，在板上查看两关的正常/反转前5、累计失误及完成状态；提供明确返回，不在成绩页调用旧app更新。关内标题继续显示方向模式，游戏/暂停/结果显示挑战用时和本次失误；通关页显示本次成绩与是否进入前5。

本版不新增清空存档入口，避免无关破坏操作。0.8.0没有档案：升级后是首次存档，第一关开放、第二关锁定；不会把此前口头通过自动转换成解锁或历史成绩。方向选择仍上电默认正常，不扩大为设置持久化。

## 已核对的SDK与候选空间

板级`ptab.json`中NOR基址0x12000000：HCPU从偏移0x00020000起8MiB；FS偏移0x009A0000、4MiB；DFU/BLE KV分别偏移0x00DA0000/0x00DA4000、各16KiB，现有区域结束于0x00DA8000。官方板卡容量16MiB。候选游戏区域为偏移0x00DB0000、64KiB，地址[0x12DB0000,0x12DC0000)，不挪动任何现有区域。

该区域是分区表未分配候选空间，不意味着已读取设备确认全空。建议A/B各32KiB，偏移分别0x00DB0000与0x00DB8000，项目分区名`maze_a`/`maze_b`、标签`MAZE_SAVE_A_REGION`/`MAZE_SAVE_B_REGION`为新命名。实际实现必须把它们写入项目本地分区表，构建核对生成地址、容量及原分区保持一致；保持原main/bootloader/ftab烧录地址，不将存档作为默认下载镜像，也不擦除整片Flash。

SDK `GetCustomMemMapSrc`支持项目本地`custom_mem_map.h`优先于板级文件；本板实际`FAL_PART_TABLE`只有`dfu`/`ble`，均使用`NOR_FLASH2_DEV_NAME`。项目本地配置保留这两项并新增游戏分区，不能直接使用通用fal_cfg.h中的示例偏移。两份数据库均以`archive`为完整档案键，属于本项目新命名，不冒充现有SDK标识符。

已核对配置`PKG_USING_FLASHDB`、`PKG_FDB_USING_FAL_MODE`、`PKG_FLASHDB_ERASE_GRAN`及API `fdb_kvdb_init`、`fdb_kv_set_blob`、`fdb_kv_get_blob`、`fdb_kvdb_control`；需要使用8192字节擦除粒度并与真实FAL设备匹配。FlashDB源码已有KV CRC与恢复检查，且存在`FDB_KVDB_CTRL_SET_NOT_FORMAT`控制；其实际恢复语义必须测试，不能简单设置禁止格式化后声称所有掉电路径可恢复。

## 档案与写入边界

使用固定容量、显式字节编码，不直接保存含指针/填充的C结构体。内容包含魔数、格式版本、长度、提交序号、规则版本、稳定关卡ID、完成/解锁状态、分模式累计失误及前5成绩、CRC。成绩按当前地图/物理规则版本绑定，后续地图改变不可静默混排旧成绩。没有RTC也能工作，不持久化传感器参考。

首次只在确认整个专用区域全为擦除值时创建新档案，先在A写入并读回初始档案。非空且没有任何可识别有效副本、或存在不支持格式版本时须显示明确错误，不静默初始化覆盖；不擅自调用清库。若一份损坏而另一份有有效同版本档案，可恢复有效档案并明确提示副本待修复，不能伪装成新玩家。任何发现的不支持版本都保留现场，不能把它当作可清除的损坏副本。

启动先分别以禁止自动格式化方式检查两份数据库及档案，选取校验通过的最高提交序号；相同序号内容应一致，不一致报错。扇区头不合法导致一份无法挂载时仍可使用另一份有效档案。提交只擦写非当前有效副本，目标允许在已经有有效本项目档案且无未知格式版本的前提下重新建库；当前有效副本不参与此次擦写。新档案整份写入且读回校验成功后才成为当前副本。重试同一RAM档案不改变玩家计数或重复插榜；内容更新则分配新的提交序号。

这两份独立数据库的策略避开“禁止格式化导致单库回收中断后根本无法进入恢复”的缺口，但仍须真实FlashDB受控中断测试证明。首次建库中断、且没有有效档案时，错误页的“重试”只重新探测；无法安全识别的半成品保持错误，不承诺点击重试必能修复，也不自动擦除它。

通关、落坑及带有尚未保存变化的退出才触发提交，游戏帧/采样/暂停浏览不写Flash。整个档案提交到目标副本，并在成功返回后读回校验。写入前关闭IMU请求，仅在启动、结果、选关或专用存储错误页执行；校准/游玩/暂停状态不执行擦写，继续前也不安排擦写。只有主线程使用该数据库，不增加后台存储线程或让它调用LVGL。

保存成功后显示已保存；失败明确显示未保存及错误码，保留RAM中的当前成绩/解锁，结果或选关页提供重试。重试提交同一份最新档案，不重新加失误/插榜。若继续操作使RAM档案更新，之后重试以最新档案为准；在未保存提示仍存在时断电，重启可能回到上次已提交进度，需要向玩家明确说明。

启动时无可用兼容档案且读取失败，阻止进入游戏并给重试入口，不静默降级到临时档；若有一份有效档案则按前述副本恢复规则处理。保存失败可以保留本次RAM进度，但错误不会被正常采样抹去；后续成功提交才清除。一次逻辑档案提交完成后恢复显示服务，耗时从真实板端测量；不能以主机速度证明UI响应。

断电一致性目标限定为：已有有效档案的更新/回收期间中断，重启得到完整旧档或完整新档，不产生解锁已更新而成绩一半等混合状态。刚落坑尚未提交就断电，允许恢复旧累计值，不承诺尚未提交的RAM操作也持久化。实际FlashDB在擦写/回收边界能否满足目标须用实际库和受控故障验证；不满足时修正存储实现，不能削弱口径或伪造通过。

## 模块、状态与验收草案

成绩纯逻辑模块维护挑战累计、一次性结算、排序及解锁；存储编码/校验与FAL适配分开；导航层负责成绩页及存储错误/未保存状态，app继续负责校准和物理。载入和保存状态不运行旧游戏，仍只有UI主线程操作LVGL。当前导航代次和页面版本策略保留。

确认设计后同步以下REQ/TC到正式需求及验收计划，未实现前不写通过：

| 需求 | 行为 | 验收 |

| REQ-033 | 挑战时间/失误及累计失误，一次性结算 | TC-044：多次落坑/重玩/退出/通关、暂停及设备恢复，时间合并和不重复计数 |
| REQ-034 | 分关分模式前5及板端成绩页 | TC-045：第5/6名、同分稳定排序、未通关不入榜、两模式隔离，真实LVGL字形/边界 |

主机先验证真实成绩逻辑、编解码、库层受控Flash写入/擦除中断；SDK构建核对启用配置、生成分区、产物及SHA；真实LVGL验证菜单/锁关/成绩/错误反馈及既有活动刷新；板端验证重启保存和实际写入耗时。故障注入与真实拔电分别标注，不拿主机注入冒充板端掉电。旧B/C不恢复，新增存档必要验证不能因此省略。

实施第一步是存储策略预研：真实库的首次建库、已建档更新、回收及两份档案切换的受控写/擦中断验证。在此门槛通过前，不接入产品UI/成绩持久化；若不满足旧/新完整恢复目标，停止采用当前存储方案并修正设计，不让后续业务实现掩盖存储缺口。

## 设计复核

独立builder check未发现需要用户另行决定的阻塞项。复核指出单库禁止格式化不是完整的断电恢复方案，已改为两个独立数据库保存完整快照、先验证库层中断；补齐首次建库中断的错误/重试边界、累计时间统一取整及模式归属。方案仍待实现预研，未宣称掉电验证已通过。

## 本阶段边界

不保存进行中游戏，不新增校准持久化、用户账号、联网排行、手动档案导出或电脑工具，不加入新机关/随机地图/看门狗。教师范围核定未知保持原记录。所有改动留本地，用户明确要求收工提交时再审查、提交和推送。

## 实施核对修订

真实flash2 FAL适配的blk_size为8192，原Kconfig默认4096不适用；当前方案显式采用8192，并保留这项纠正的研发记录。探测不完整数据库时FlashDB仍可能写恢复标记，新增项目专用maze_flash设备和逐副本写闸门：默认只读，提交只允许目标副本；底层使用真实rt_flash_read/write/erase，检查返回值。原dfu/ble仍用NOR_FLASH2_DEV_NAME；maze_a/maze_b改用maze_flash、相对偏移0/32768，物理范围仍是已批准的0x12DB0000至0x12DC0000，不移动其他分区。不得把代理相对偏移误当芯片偏移。

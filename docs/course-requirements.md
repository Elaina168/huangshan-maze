## 2. 课程底线

| 编号 | 要求及性质 | 来源 | 项目落实与证据 |
|---|---|---|---|
| C-01 | 明确要求：交付真实可运行的使用闭环、可复现工程和研发过程材料 | 手册 p1；简介 p3 | 产品需求、真机演示、构建说明、代码与过程文档 |
| C-02 | 明确规则：1-5 人可组队，个人与多人项目遵守同一质量底线，人数不机械决定功能数量 | 手册 p1；简介 p5 | 本项目为 1 名学生，AI 是辅助工具，不是第二名学生成员 |
| C-03 | 明确要求：黄山派必须有实际产品用途的软件开发或修改，参与联调和验收；仅烧录现成固件不满足要求 | 手册 p1 | 自己实现迷宫规则、控制、交互及验证，区分已有示例与新增工作 |
| C-04 | 明确要求：全程使用 Git，保留产出与完整历史；个人成绩依据个人提交历史认定 | 手册 p2；简介 p5 | 从工程建立开始提交需求、设计、源码、测试与开发记录；构建产物处理见 C-27 |
| C-05 | 明确要求：真实黄山派完成核心闭环验收，模拟、编译或视频不能单独替代实物验收 | 手册 p3 | 最终对应版本的构建、烧录、真机测试及现场运行 |
| C-06 | 明确要求：独立完成一次可观察修改、编译、烧录和验证，展示提交并解释修改入口、行为及验证方法 | 手册 p8 §3.2 | 单独保留一次本人修改的提交和前后实测；运行原样示例不能替代 |
| C-07 | 明确要求：如实报告重要缺陷，不伪造测试或贡献记录 | 手册 p3、p12-13 | 通过、失败、未执行分别记录，保留失败和修复后的重测 |

课程不要求设计电路板、结构件或量产方案（手册 p1）。可以有手机、电脑、云端和外接模块，但这些不是每个项目必须具备的组成。

| C-12 | 明确要求：需求变更记录前后、原因及验收影响；涉及必达范围时与教师确认 | 手册 p9 §4.4 | 需求变更记录，不在结题前悄悄删除未完成功能 |
| C-13 | 明确工程规则：新增功能前先写需求、验收条件和状态/数据路径；职责与依赖保持清楚 | 手册 p8 §3.3 | 先完成需求和设计，再写产品代码 |
| C-14 | 课程建议：至少提供系统架构图、数据流图、状态机图；图要可读并与实现一致 | 手册 p9-11；简介 p23 | 本项目采纳三图：模块与接口、采样到显示的数据、开始/暂停/结束/错误等状态 |

简介 p22 用 L1 用户故事、L2 功能需求、L3 非功能需求、L4 约束讲解需求层次。项目文档覆盖这些内容；示例中的配速刷新间隔等数值不是迷宫要求。

三图应说明：模块对应哪些代码；关键数据格式、单位、更新周期与生产者/消费者；事件与状态转换；重复操作、取消、返回重入和错误恢复的行为。是否采用 Mermaid 不强制（手册 p9-10）。

## 4. 平台、实现与过程管理

| 编号 | 要求及性质 | 来源 | 项目落实与证据 |
|---|---|---|---|
| C-15 | 课程技术基线：SiFli SDK v2.5.1、RT-Thread、LVGL v9，板型 sf32lb52-lchspi-ulp；其他技术允许，但需说明与复现方法 | 手册 p4；简介 p19 | 已沿用该基线，实际工具链与配置见各次构建证据 |
| C-16 | 明确要求：有图形界面的项目使用 LVGL | 手册 p4 | 迷宫显示与触摸交互使用 LVGL |
| C-17 | 明确工程规则：只有 UI 线程操作 LVGL；耗时工作放后台，用消息或受保护快照交换数据 | 手册 p8、p12 | 分离 IMU 采样、运动/规则、显示；明确共享数据所有权与同步方式 |
| C-18 | 明确工程规则：小步可验证增量，保持主线可构建；一致风格、边界检查、错误返回、人工维护配置 | 手册 p11 §6.1 | 每次实现相关功能后验证；不只修改自动生成头文件 |
| C-19 | 明确工程规则：等待操作有超时或取消，退出后的后台行为要显式设计，新旧异步操作不能互相覆盖 | 手册 p12 §6.2 | 暂停、退出、重玩停止或重置相关工作；处理迟到的采样结果 |
| C-20 | 明确要求：日志可辨模块、事件、结果；异常附错误与状态；开发日志记录任务、决策、问题、验证和提交 | 手册 p12 §6.3 | 保存文字日志，控制采样日志频率；不以图片替代可复制的日志 |
| C-21 | 明确要求：重要 AI 使用记录任务、采纳结果与验证；能解释、修改和验证本人工作 | 手册 p4、p12；简介 p7 | 记录设计、关键实现和修复中的 AI 协作，不虚构人工修正 |
| C-22 | 明确要求：维护第三方资源来源、版本、许可和修改情况，区分个人成果与复用 | 手册 p4、p12；简介 p7 | 登记 SDK、LVGL、示例代码和素材，不把复制代码算为全部个人贡献 |

课程不强制归档全部 AI 聊天数据，不设原创代码比例（手册 p4）。Git 分支与 PR 推荐但不强制，远程仓库推荐但不要求公开（手册 p11、p15）。本地提交标题采用“类型(模块): 本次变化”，重要提交说明原因、修改和验证（手册 p15）；使用脚手架时再核对其更具体的钩子要求。

开发前检查实际板卡资源。课程未提供震动马达、TF 卡和电池（手册 p5），不能默认依赖这些附件。若采用音频，确认 SPK 接口；无音频可不接喇叭（简介 p19）。

## 6. P09 体感迷宫：题库参考与当前落实

来源：手册 p20 说明题库性质，p23 的“P09 体感迷宫”。P09 是基础至综合、建议 1-4 人的参考题；难度不对应成绩上限。“甲”只代表存在相关接口示例，不代表整题已实现。

| 题库原意 | 我们应如何落实 | 状态 |
|---|---|---|
| 通过倾斜控制角色，完成有起点、终点和失败条件的关卡 | 明确地图、目标、控制方式和失败规则 | 已实现四关；撞普通墙阻挡，落坑失败，到终点胜利；第四关支持检查点复活 |
| 最低闭环：开始、校准、移动与碰撞、到达或失败、暂停、重玩 | 逐项建立产品需求和验收用例 | 已建立 PRD、验收用例并实现闭环；已有用户板端正常反馈，完整验收另见测试报告 |
| 四向操作正确 | 定义舒适握姿、屏幕坐标与 IMU 轴映射；上板逐向验证 | 正式方向为 USB 在屏幕右侧，提供正常/反转模式；已有采样、软件测试及用户操作反馈 |
| 碰撞边界稳定 | 测试墙边、拐角、极端倾斜等相关边界 | 纯逻辑碰撞、惯性路线及陷阱回归通过；不将此视为板端全部边界已量化验收 |
| 多次进出和重玩不耗尽内存 | 定义循环次数、持续时间与资源记录方法 | 已有历史资源记录和软件回归；用户已停止旧 B/C 批次，未执行部分不判通过、不自行恢复 |
| 报告资源与手感验证 | 保留内存/栈等记录和控制体验测试条件 | 钢珠惯性及普通/冰面已有用户反馈；当前阶段有总体正常反馈，最新 free/ps 与时序量化仍待证 |
| 风险：旋转/透明层临时缓冲，帧率影响物理速度，音频供数阻塞 | 设计资源预算与运动时基；采用相关能力时验证 | 已分离物理时基、采用局部视口和显示完成等待；SDK 构建/静态预算及软件回归已做，实机量化仍待补；音频不在当前范围 |
| 可参考 pelican-ride.md 与模型/UI 分离；换皮不能视为全部贡献 | 仅提取需要的接口或结构，记录迷宫规则与验证的新增工作 | 已有模型/输入/地图/界面/存储模块与[第三方清单](../THIRD_PARTY.md)，AI 与人工贡献按日志如实区分 |

关卡编辑、道具、难度、音效是题库拓展项，不是课程全部必做。第一版单关卡范围已获用户确认并实现，后续按用户批准的[实施路线](roadmap.md)扩展；截至本次已完成第4阶段软件及构建，并获本轮板端总体正常反馈。现有四关、钢珠惯性、多种地面、选关/反转、成绩/失误/解锁存档、钥匙/开关/门、破墙、检查点复活均有对应需求与测试。后续阶段尚未实现，不把路线列项当成果。

失败规则已在 PRD 明确，不再沿用“待确定”的早期描述。用户要求产品在板上独立操作；未接喇叭和振动马达，音效/蜂鸣/振动暂不做，不安排电脑端用户工具。开发、烧录和必要验证仍使用电脑。教师立项核定及必达范围变更审批未记录，不能以用户功能确认冒充教师审批。

## 8. 交付材料检查表

- [ ] 产品需求规格：用户场景、必达/拓展、量化判据、异常与变更。
- [ ] 方案设计：职责、接口、关键数据、状态、资源、技术取舍；本项目采纳三图。
- [ ] 测试计划：用例、关联需求、步骤、预期、证据、环境与准出条件。
- [ ] 测试报告：实际结果、失败与修复回归、版本、资源和已知限制。
- [ ] 开发日志：日期、本人任务、决策、问题、验证、提交、重要 AI 协作。
- [ ] 第三方资源清单：来源、版本、许可、修改与贡献边界。
- [ ] 研制总结：成果、本人实现、关键问题、验证和限制。
- [ ] 源码及完整 Git 历史、交付 tag；推荐 Git bundle 并验证恢复。
- [ ] 对应版本的可烧录固件、完整烧录配置和固件校验清单。

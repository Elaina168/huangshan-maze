## 烧录

1. 插好板子的USB，确认Windows当前识别的实际USB串口，不选择蓝牙串口；历史COM6不能当成固定端口。
2. 关闭占用该串口的监视器。在PowerShell执行：

```powershell
$mazeBuild = Get-Content -Raw -Encoding UTF8 'D:\codex\黄山派\build\build-state.json' | ConvertFrom-Json
Set-Location (Join-Path $mazeBuild.stage_path 'project\build_sf32lb52-lchspi-ulp_hcpu')
$env:Path = 'D:\sifli\tools\tools\sftool\0.2.5;' + $env:Path
.\uart_download.bat
```

3. 根据脚本提示输入当前串口数字，例如实际为COM6才输入6。这套命令不需要重新激活SDK，也不会从其他目录错误查找bootloader/main/ftab。若拒绝访问，先关闭串口监视；若未找到设备，重新核对USB连接和实际端口。
4. 下载成功后按复位键，或重新插拔USB，再打开该串口。新版启动应包含`[huangshan_maze] v0.4.3-pause-feedback boot ok`与`[maze_ui] ready`。屏幕出现TILT MAZE和Start。RGB应熄灭；注意BAT座旁常亮绿灯是供电指示灯，不能用它判断RGB是否关闭。构建哈希不能代替板端启动确认，记录本次使用的构建清单。

## 操作

- 蓝球是玩家，灰墙会阻挡，红洞是陷阱，绿色圆是终点。小球中心进入红洞失败、进入绿色区域胜利；撞墙不失败。
- Start：保持舒适姿态放稳，自动收集20个稳定样本，正常约1秒；这是一次校准，不需要操作20次。成功后才开始移动和计时。3秒内未满足稳定窗口条件会提示失败，放稳后Retry。校准过程中Cancel返回准备。
- 向屏幕哪一侧压低，小球应向哪一侧移动。无需重新采集原始四向IMU日志，本次直接验证可见运动。
- Pause：暂停位置和时间。Resume继续；Calibrate保留当前位置和用时重新校准，成功后仍暂停；Replay清空本轮并重新校准；Exit回准备。
- 结果页：Replay重玩，Exit退出。胜败后倾斜不再改变位置和用时。
- 校准失败：放稳后Retry。设备错误：位置/用时冻结，Retry重新校准，成功后停在暂停页，需要明确点Resume。错误编号用于保留原始故障信息，不是掉入陷阱。

暂停重校准失败仍应回暂停、保留旧参考/位置/用时。0.4.2的-1003标题会被下一条健康采样清除；0.4.3保留这次失败提示直到离开暂停或开始新的校准，实时传感器错误优先显示。健康采样后Resume仍可用旧参考继续，提示保留不表示必须重新校准。只倾斜到某个姿态然后保持稳定，仍可能成功；失败条件是3秒内始终没有满足20点稳定窗口。

0.4.2校准进度和暂停提示位于顶部，地图保持可见。正常Start成功应直接游玩；设备错误后的Retry成功才回暂停。此变化用于避免进入游玩时擦除中央大面板，不改变校准和恢复规则。

## 先做基本接入检查

2026-10-25用户要求剩余项目集中完成：现有基础结果沿用，下一批直接按[完整集中测试清单](maze-final-test-batch.md)执行并集中反馈，不必逐项等待回复。清单区分真实板端、视频测量、主机注入及当前固件暂不支持的验证入口。

不要求本阶段重复五轮。分步保留实际结果，不将未操作的项目写通过。

1. 首次烧录后先确认页面完整、按钮可见、灯已灭；贴启动和Start校准日志。若显示/校准不正常，先停在这一步处理。
2. 校准后轻倾四向，记录实际可见运动是否对应；中立放稳观察小球。先检查方向，再尝试通关。
3. 向墙倾斜应阻挡，沿墙倾斜应能滑动。暂停约10秒观察位置/用时，再继续；暂停重校准后不应自动继续。
4. 主动进入一次红洞，确认失败/冻结；重玩后尝试绿色终点，确认胜利/冻结。可行路线：从左上向下绕过第一面墙底部，向右进入中间通道，再向上绕过第二面墙顶部，向右、向下到右下终点。遇到陷阱时可绕行。
5. 退出回准备，重新Start应重新校准、从起点和零用时开始。正常操作中尝试快速重复点击，观察是否出现多次跳页或旧操作生效；保留日志，不故意制造内部传感器物理故障。
6. 在首次准备页和上述操作后回到准备页，分别发送`free`、`ps`，保留原始输出。应仍只有一个maze_imu应用采样线程和一个main/UI线程，其他系统线程按原样记录；堆与栈峰值如实比较，单次值不能判断无泄漏。

一轮基本接入与正式验收不同。独立计时/响应、显示帧率、50轮及至少30分钟资源测试在参数确认后按TC计划另做。

## 日志字段

`[maze] event=... state=... gen=... tick=...`记录触摸消费时刻。状态变化和每约500ms输出含`ms`有效用时、`pos`局部地图球心（像素，日志取整数）、`input`死区后raw输入和`error`。50ms刷新调用不是实测屏幕帧率，日志tick也不是物理倾斜起点。

状态编号：0准备，1校准，2游玩，3新轮校准失败，4设备错误，5暂停，6胜利，7陷阱失败。事件编号：0开始，1暂停，2继续，3暂停重校准，4重玩，5重试，6退出/取消。`calibrated ref`只在校准成功时输出，继续不应重新输出校准成功。

错误：-1001样本过期，-1002读取间隔超限，-1003校准超时，-1004主循环时序间隔超限；其他非零值保留实际I/O返回。附原始上下文以便定位，不将这些错误解释成玩家失败。

先只验证Start校准后能否进入游玩、Resume后是否仍报错，不重做整套验收。若出现设备错误，保留之前几行及新增的`[maze_timing]`两行：loop/service/render为主循环、LVGL服务及对象更新的tick；read/age为最新样本读取时间与年龄，consumed_gap是跨消费快照的时间差，producer_gap才是实际相邻读取间隔；producer_gap_count保留会话中真实超限次数，健康新快照不会抹掉既有异常。

0.4.2已收到用户反馈：一次重试后胜利、重玩后陷阱失败并退出，本段无-1002/-1004；尚无完整暂停恢复、资源或长时验证。见[本次板端记录](../../evidence/ui/2026-10-25-active-view-board-01/README.md)。

用户照片与官方板卡介绍交叉核对后确认：所指常亮绿色小灯是BAT座旁的供电指示灯；RGB是另一颗白色方形灯珠，照片中未发光。撤回将该绿灯认作RGB关闭失败的判断；不再为这颗供电灯修改RGB驱动或重复烧录。见[照片与官方标注证据](../../evidence/ui/2026-10-25-led-identification-01/README.md)。

当前固件`pin_func=643 expected=477`比较了不同层级的功能枚举；643是正常PA32_TIM，477是逻辑GPTIM2_CH1，SDK会进行转换。因此`restored PA32 PWM mapping`不能说明曾有异常映射。这是当前诊断代码的已知问题，尚未更新固件；PWM周期/脉宽读回也不是光学反馈。`maze_rgb_off`控制RGB，不控制供电指示灯；不要为此改动共享LDO。

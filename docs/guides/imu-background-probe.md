# 后台IMU采样与界面并行预研

对应实现计划Task 2，关联REQ-003/010/011/013、TC-013/014/015/017/018的后续实现；不是正式迷宫验收。本版保留显示测试，没有小球或校准。

## 操作

1. 正常使用朝向统一为USB在右、屏幕文字正向。版本为 `0.2.1-imu-background-probe`，页面标题IMU BACKGROUND PROBE，标记USB RIGHT。
2. 烧录后先不点击CENTER，采样应为OFF。串口发free、ps，保存堆/栈输出；maze_imu线程应已存在并等待请求，不应周期打印采样。
3. 点击CENTER一次，出现ON与request generation=1 sampling=on。后台约50ms间等待读取，主线程最多每500ms打印一份raw快照；倾斜观察数值变化，同时依次点击四角，检查界面持续可操作。
4. 再点CENTER，出现OFF与新代次。后台结束已在途的I2C工作并恢复寄存器；不再启动下一次采样。已经进入驱动的阻塞调用不能强制中断，旧结果不作为当前代次输出。若打印restore_error，保留原日志，停止继续测试并报告。
5. 本阶段先完成一轮开启、采样期间四角操作、关闭，再在OFF状态查询free、ps即可作为基本接入检查。2026-10-17用户选择不重复五轮；五轮不是课程必达门槛。反复启停、线程/对象增长和长时资源检查保留到后续稳定性测试，单轮不据以认定无泄漏。

raw为传感器原始单位，尚未应用校准、死区或USB右方向转换；本阶段不要求按方向重新采集原始四向日志。序号可能跳跃，因为只显示最新副本并限频打印；不把跳号直接判为采样失败。

产品初始化后，旧imu_probe与imu_control_probe命令返回忙并说明product sampler owns IMU，即使当前OFF也不会让串口探针接管硬件；这样避免启停期间与恢复寄存器竞态。需要重跑原探针时使用历史诊断版本，而不是同时运行两个访问者。

## 烧录环境

SDK激活失败并不一定影响已有烧录工具。确认实际端口并关闭串口监视后，可以在本次构建目录直接执行：

```powershell
& 'D:\sifli\tools\tools\sftool\0.2.5\sftool.exe' -p COM6 -c SF32LB52 -m nor write_flash 'bootloader\bootloader.bin@0x12010000' 'main.bin@0x12020000' 'ftab\ftab.bin@0x12000000'
```

COM6仅为当前已使用端口，变更时按实际设备修改。新构建目录由本次build/build-state.json确定，不能误用上次显示原型目录。烧录完重新打开串口，保留启动、启停、四角点击、错误与两组资源完整记录。

## 证据边界

主机I2C/调度桩只验证请求、快照、错误及寄存器访问顺序，不等于板端任务并行或长期可靠性通过；实际后台线程栈2048 B、优先级11为试验配置，需查询ps验证峰值。已有显示版本的堆/栈记录不能代替本版记录。错误时本轮停止采样并显示OFF，下一次CENTER才重新尝试，不能无限重试掩盖错误。

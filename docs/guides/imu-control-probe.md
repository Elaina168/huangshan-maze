# 校准、死区与输入时效：串口预研

本轮在RGB工程增加`imu_control_probe`。参数经过已有数据的离线回算，但仍是预研候选，不是迷宫产品验收基线。构建、实际下载目录及固件哈希见[本轮构建证据](../../evidence/builds/2026-10-10-imu-control-01/README.md)，原`imu_probe`仍可使用。

## 1. 先验证中立

停止串口监视，在本轮构建目录运行`uart_download.bat`并等待下载/校验完成，再连接串口：1000000波特率、8N1、无硬件流控。当前端口仍是COM6时才输入6。启动文字依旧是本人修改的v0.1.1，新增命令与固件哈希用于区分本轮固件。

屏幕朝上、USB口在屏幕左侧。先保持舒适中立姿态，发送以下文本并附回车/换行：

```text
imu_control_probe
```

命令不带姿态参数。先保持稳定，等`[imu_control] calibrated`出现；这时才确定本轮参考。第一组继续保持该姿态，等约5秒输入记录结束，把从begin到end的完整日志发给Codex。

预期：稳定20点后出现`ref_raw`，随后`valid=1 xy=...`，最后`end result=ok`。理想中立输入经死区输出`xy=0,0`，真实手持情况以日志为准。不要把这一步记为5秒球心漂移测试，当前没有小球或界面。

## 2. 校准后再倾斜

中立组核对成功后，分别重新执行命令。每次都先中立校准，看到`calibrated`后再倾斜并保持到结束；不要沿用旧`imu_probe`的“先倾斜再发命令”步骤，否则倾斜会成为本轮参考。

| 记录的姿态 | calibrated之后操作 | 主要输出符号 |
|---|---|---|
| right | 右边缘低、左边缘高 | xy第一个数为正 |
| left | 左边缘低、右边缘高 | xy第一个数为负 |
| up | 上边缘低、下边缘高 | xy第二个数为负 |
| down | 下边缘低、上边缘高 | xy第二个数为正 |

xy是减参考并扣除300 raw死区后的控制输入，不是速度、角度或屏幕像素。其他轴有非零值不必然表示方向错误；要结合主要方向和操作判断。保持同一USB与屏幕朝向，保存每组完整日志并说明操作。

## 3. 校准失败与重试

四向成功后再做晃动组：从命令开始持续改变姿态，使20点窗口任一轴范围超过300 raw，直到出现`event=calibration_timeout`。预期不出现`calibrated`或有效控制输入；随后放稳并重新执行，应能独立取得新的参考。轻微晃动可能仍在阈值内，以实际日志为准，不编造失败结果。

若`valid=0 xy=0,0 event=stale_input`，命令将结束，不继续输出旧倾斜；保留日志中的`age_tick`和`gap_tick`。出现读取/身份/保存/恢复错误，保存完整输出，先核对问题。主机注入已覆盖过期输入，真实消费时效还待本轮数据验证，不需要人为制造硬件断线。

## 4. 参数与限制

20个连续有效点，窗口跨度至少950ms，XYZ每轴范围≤300 raw；稳定窗口滑动检查，校准预算3000ms。相邻读取开始间隔或读取开始至消费检查的年龄>100ms时无效；日志`tick_hz`给出tick换算率，当前配置为1000。时间戳是软件读取开始的保守参考，无法证明器件内部采样的精确年龄。

器件配置104Hz/±2g，命令每轮等待50ms，实际间隔受读取、串口和调度影响。5秒为控制记录的逻辑预算，SDK阻塞I2C和配置恢复可能延长整个命令的墙钟耗时，3秒不是命令总耗时硬上限。命令占用msh线程，RGB继续闪属于预期；当前没有LVGL、速度曲线、长期采样任务或迷宫状态机。

# 第8阶段：看门狗与默认灯效

当前版本`0.16.0-watchdog`。沿用四入口、黑暗/反转开关和固定关每关可见前5；随机只娱乐。此版无需清档，不改存储分区或v7档案格式。

## 变化

RGB默认开启，选关页不再有灯效按钮。菜单低亮呼吸，机关和胜败给短提示，游玩平时熄灭。若驱动写灯失败，本次启动停止灯效，串口打印`[maze_feedback] rgb_error=...`，选关页显示“灯效：故障 RGB (...)”；重新启动时重试。BAT附近常亮的供电指示灯不是此RGB灯效。

主循环完整完成后才喂硬件看门狗；运行窗口5秒、喂狗间隔至少250ms，启动初始化窗口30秒。采样/物理原有100ms保护保持，出现设备错误仍可在错误页人工重试，不应立即反复重启。显示、RGB或其他步骤长时间不返回，不能由空闲线程或flush服务代喂。

## 一轮新增短测（TC-085）

1. 启动日志应有`v0.16.0-watchdog`、`[maze_wdt] boot result=0 window_s=30`、`running result=0 window_s=5 feed_ms=250`。确认无灯效开关、菜单呼吸；已有前5和解锁仍在。
2. 任选已解锁固定关，校准后移动/暂停/继续/黑暗滚动，观察没有误重启或遗留黑块；机关及胜败短灯效可顺手观察，不要求重新刷满排行榜。
3. 随机生成或换图一次，返回选关，等待现有保存结束；正常重启后检查已保存成绩/解锁/随机身份。保存/生成不得误触发看门狗。
4. **故障注入是主动重启测试**：留在选关页、确认保存已结束，再输入`maze_watchdog_test confirm`。应出现`[maze_wdt] test stall main_ms=15000`，随后主循环停顿并重新启动，回到选关页，旧成绩/解锁保留，不能自动恢复旧游戏或重复注入。记录从注入到新启动的实际时间及日志。其他页面只打印`test rejected page=...`，不执行停顿。
5. 最后在选关页贴一次`free`、`ps`，说明有无误重启及灯效情况即可。不重开旧B/C批次。

5秒是候选正常WDT超时，不是已经实测的复位时延。SDK驱动在52X的NMI转入应用回调后调用PMU复位；若中断路径也失效，仍依赖芯片二段硬件复位，耗时可能更长。主机设备替身/离屏和构建不能证明实际复位或物理掉电。

```powershell

```

烧录后重新连接串口，按TC-085一轮短测即可。

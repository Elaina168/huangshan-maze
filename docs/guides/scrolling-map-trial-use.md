# 大地图跟随镜头试验

本轮是独立试验，不是正式第三关。地图700×600，屏幕显示350×300局部区域；球、墙和物理参数不缩小。正式两关及档案格式/分区保持。

## 启动与操作

烧录本轮试验构建后，启动版本应为`0.9.3-scroll-draw`，界面标题为“大地图 | 试验 | 不保存成绩”。不需要串口指令；屏幕点“开始”，板子放稳约1秒完成20点校准后游玩。

地图由三段横向区域从端部相连。先向下找到第一段横向冰面，再向右到端部，向下进入第二段，再向左、向下进入第三段，最后向右寻找绿色终点。普通/冰面手感沿用原版，红色陷阱可绕行。本图用于验证滚动与折返，尚非正式机关关布局。

镜头在小球离开中央区域后平滑跟随，到地图边缘停止。标题、时间、按钮固定；暂停时镜头冻结。暂停页可继续、校准、重玩、退出。退出回试验准备页，重玩重新校准并复位镜头；设备错误恢复后仍需点击继续。

## 一次短测

1. 开始并校准，向右和向下移动到发生滚动，观察小球、墙和冰面是否平稳，有无闪烁/拖影。
2. 往相反方向倾斜并折返，检查镜头是否自然、球始终可见，是否容易看清前方。
3. 到右侧/下侧地图边缘，镜头应停止且不露出地图外空白；沿路径返回左侧时同样检查。
4. 滚动中暂停，画面与计时应冻结；继续不跳镜头。暂停后重玩，应回起点重新校准；退出后可再次开始。
5. 绕开红坑走到绿色终点，再重玩主动落坑，检查胜败提示和停止行为。

一次完成即可，不恢复旧B/C。反馈是否卡顿、跟手、眩晕或看不清前路；若出现-1002/-1004、球出视野或明显停顿，请保留前后`[scroll_trial]`日志。不要修改100ms阈值。串口只用于开发诊断，游玩不依赖电脑。

## 2026-11-02时序修复复测

0.9.1已收到真实-1004失败反馈，旧试验固件不作为可玩通过版本。当时提供0.9.2-scroll-service；本页命令现已更新为后续0.9.3。该修复在40行条带提交回调返回后服务采样和物理，100ms检查不变，整帧绘制开销并未降低。

本轮只需重复原路径：开始校准后向右到冰面附近，越过原x246位置，继续横向滚动并折返，暂停再继续。如果出现故障，再走重试—校准—继续，贴首次异常前后日志。日志新增physics_gap_tick（日志窗口内实际物理服务的最大tick间隔）和flush_services（窗口内条带服务次数）；loop_tick仍可能包含完整一帧，所以须同时看实际服务间隔。单条带真阻塞超100ms或没有新采样仍应报错。

软件受控复现/回归、真实LVGL及完整SDK构建通过；真实板端修复效果尚待本次复测。无自动烧录或提交推送。

## 0.9.3小球闪烁复测

本轮合并旧/新球擦画区域，并把试验活动绘图缓冲改为单份390×300 RGB565视口规模缓冲，避免把球切到多个提交中；不缓存700×600整图。静态RAM增加234000B，目标ELF未分配尾区119092B，这不是运行时可用堆。

确认启动0.9.3-scroll-draw，日志`[scroll_draw] buffer_bytes=234000 single=1 rows=300`。分别试镜头不动时移动球、镜头滚动与折返，观察闪烁是否改善，同时确认不再出现-1004。然后执行一次`free`、`ps`并贴结果，连同几行`[scroll_trial]`日志核对physics_gap_tick与实际资源；不要求50轮或30分钟。

如果出现真实单块超100ms仍应报错；本轮没有放宽检查。软件逐flush追踪与完整构建通过，实际LCD扫描的观感及新缓冲下的时序/资源仍待用户反馈。回退可用前次0.9.2或正式版自己的三文件，不能交叉拿产物。

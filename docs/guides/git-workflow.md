# Git 开发与推送规则

依据课程清单 C-04、C-18、C-20、C-21、C-27、C-28，以及用户2026-10-17更新的要求：工作中先做，明确说“今天到这”时再统一提交并推送GitHub。

1. 开工看 status、最近历史、需求和开发日志；一个提交解决一个相关问题。
2. 需求与测试先行，重要变更写明原因与关联需求；完成必要检查后审查 diff，再暂存明确文件。
3. 标题 `类型(模块): 具体变化`，正文包含背景、改动、验证、AI协作四项，不伪造人工修正和硬件结果。
4. 收工写当天日志，标注实际结果和未执行项；commit-msg 自动运行项目检查和提交格式检查。
5. 平时完成相关验证并保存本地文件；用户说“今天到这”后，审查当天差异，明确相关文件，运行提交检查，再commit并push。此前不自动暂存、提交或推送。初始基线用main，未来较大功能建议独立分支；不强推，不重写已推送历史。
6. 在 GitHub 查看远端提交和 CI；如网络或鉴权失败，保留本地提交，报告具体失败，不说已推送。
7. 源码平时排除 build、SDK、缓存和密钥；最终固件另行交付，tag 与完整历史按课程标准归档。

首次导入只创建今天真实的新提交，已发生的早期工作以证据与说明归档，不人为设置过去提交时间。

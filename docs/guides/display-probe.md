# 显示与触摸预研：烧录后怎么测

对应实现计划Task 1，支持REQ-001/013/015/016和TC-001/017/018/020/021的后续实施。本页仅测显示接入与坐标，不是正式迷宫验收，也没有小球或关卡。

后续修正：0.2.0页面USB LEFT是预设提示，用户实测正常显示时USB在右；后续版本改为USB RIGHT。USB左仅保留为旧IMU实验朝向，不继续要求使用该朝向。

## 1. 本版变化

程序版本 `0.2.0-display-probe`，日志前缀 `[huangshan_maze]`、`[display_probe]`。启动后关闭RGB灯，主线程运行LVGL；原来的循环亮灯日志消失。旧RGB修改与预研证据仍保留，尚未新增IMU后台线程，原串口IMU命令仍在。

界面使用SDK自带Montserrat字体的英文标记，避免引入中文字库影响本轮资源测量：TL左上红色、TR右上绿色、BL左下蓝色、BR右下棕黄色、CENTER中央紫色。四角目标内缩以避开圆角屏的不可见区域。细边框用于观察裁切，四角不是物理最外侧像素测试。

## 2. 烧录

1. 板卡为黄山派 `sf32lb52-lchspi-ulp`，连接电脑。实际端口从设备管理器或串口工具确认，不能永远假定COM6。
2. 关闭串口监视窗口，释放串口。
3. 查看仓库 `build/build-state.json` 的 `stage_path`；切到该快照下的 `project/build_sf32lb52-lchspi-ulp_hcpu`，再运行 `uart_download.bat`。必须先切目录，避免跨盘和相对固件路径错误。构建成功后助手会提供本次确切路径。
4. 下载器询问端口号时输入实际数字，例如COM6对应 `6`；按已有成功流程完成下载和校验，保留结束日志。
5. 下载器结束后重新打开串口监视；若仍在下载模式，按此前已验证的复位方式或重新插拔USB。观察启动版本与 `ready` 日志，不能只看固件下载成功。

## 3. 按顺序测试

后续统一屏幕朝上、USB口在右边；用户已确认此时文字正向显示。如果文字倒了、四角位置不符或触摸落到别处，先保留现象，不旋转板卡掩盖问题。

| 步骤 | 操作 | 预期与应保留记录 |
|---|---|---|
| D-01 | 查看启动和全屏 | 标题DISPLAY PROBE、尺寸及USB LEFT可读；有ready日志；无闪灯；记录是否旋转/镜像/裁切 |
| D-02 | 依次点TL、TR、BL、BR中心，每次点后松手 | 日志target依次相符；TL/TR的y较小，BL/BR的y较大；TL/BL的x较小，TR/BR的x较大 |
| D-03 | 点CENTER并松手3次 | 每次完整点击计数只加1；画面显示最近按下坐标及总Clicks；保留三次click日志 |
| D-04 | 静置10秒，再重复D-02和D-03 | 页面仍能操作，无异常重启或持续日志刷屏 |
| D-05 | 串口依次发free、ps，再完成10次CENTER点击后再发free、ps | 保留两组完整输出与步骤位置；记录main栈历史峰值及堆变化，不据一次结果判定无泄漏 |

当实际显示为390×450时，目标中心理论位置约为TL(76,64)、TR(314,64)、BL(76,386)、BR(314,386)、CENTER(195,225)。这是由布局计算的参考，不是实测或触摸精度验收；手指落点不必等于理论中心。

串口通常每次按下与点击分别输出一行，例如：

```text
[display_probe] ready width=390 height=450 tick_hz=1000
[display_probe] press target=TL x=76 y=64
[display_probe] click target=TL count=1
```

以上是格式示例，不能作为运行证据。完整点击指按下后在目标内松开；滑出后松手可能没有click，属于LVGL行为。屏幕空白区域不计数。

## 4. 结果与下一步

提供启动日志、D-02/03点击日志、两组free/ps，并说明文字方向、四角位置和灯是否已关闭。若不正常，保留错误与实际画面；暂不进入后台采样和地图实现。

真实资料保存到当日 `evidence/display/日期-ui-01/`，原附件保存原字节；聊天直接粘贴标注转录。文件应记录板型、构建清单、固件校验值、步骤、预期/实际/结果。没有设备固件独立校验就不声称设备哈希已读取。

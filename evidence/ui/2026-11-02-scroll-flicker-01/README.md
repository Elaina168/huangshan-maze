# 小球闪烁：逐提交复现与软件修复

2026-11-02，关联REQ-037、TC-051/052。用户反馈0.9.2时序异常不再出现，但镜头滚动与不滚动都可能闪球。该反馈仅确认本轮异常总体改善，不宣布完整时序/资源验收。

## 实际复现

- red.log：真实SDK LVGL、RGB565、40行旧缓冲。镜头不滚动时球横向移动超过直径，逐flush监测屏幕已有像素，完整球128像素降为0；不是只看终帧截图。旧球/新球分离失效区先后提交会出现空档。
- union.log：仅合并旧/新球绝对屏幕矩形并由固定view裁剪后，不滚动最少128保持；滚动仍最少80/128，在条带边界仍被分割，测试按预期失败。
- green.log：增加试验单份390×300 RGB565绘图缓冲（234000B、64字节对齐）后，不滚动和180帧滚动的每次flush返回后均至少128球像素。提交次数由union阶段878降为500（包含10帧不滚动及180帧滚动），总像素量最大122100不变；裁剪/固定HUD/旧点击/暂停重玩通过。主机LVGL可用堆38528前后一致，但新增234000B属于静态RAM，不能从此数字推断目标可用堆。

## 实现与边界

仅MAZE_SCROLL_TRIAL分支替换LVGL应用绘图缓冲，继续部分刷新，不创建700×600整图位图；原SDK小缓冲仍占静态空间但不再作为试验的活动绘图缓冲，不编辑SDK。单缓冲被复用前仍走SDK wait_flush_done等待DMA，不能覆盖在途数据。0.9.2纯app服务回调及100ms故障检测保留，较大单块可能降低服务频率，因此必须重新测physics_gap_tick，而不能沿用0.9.2反馈。

旧ARM ELF SRAM尾区353132B；新增缓冲后需新ELF与板端free/ps核对。静态复核未发现确定阻塞缺陷，指出DMA提交返回不代表物理扫描完成，以及单块时序/RAM待实测风险，均保留。

软件逐提交完整不等于物理屏幕扫描完全不闪；新版构建与真实复测结果另记。无自动刷机/提交推送，不恢复旧B/C。

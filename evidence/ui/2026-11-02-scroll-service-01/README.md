# 滚动时序错误修复：软件证据

日期2026-11-02。失败原貌及真实128ms间隔见[板端失败记录](../2026-11-02-scroll-trial-board-01/README.md)。关联REQ-037、TC-051/052。

根因：真实SDK使用40行双部分缓冲，LVGL一次timer_handler内连续渲染/提交整片失效视口；原runner仅在handler返回后更新物理。x246进入镜头跟随后loop128ms触发-1004。校准成功并不能消除该阻塞。

本轮在仅试验构建的LV_EVENT_FLUSH_FINISH事件服务最新采样、实际物理时基与采样请求。SDK在flush_cb返回后同步触发该事件，不代表LCD DMA已经物理完成；服务仍发生在UI线程，不触碰LVGL对象/触摸或存档。每次先让出一tick供低优先级IMU运行。场景对象一帧内保持原快照，下帧再反映app终态。

- 先修改真实runner测试为8×16ms绘制块；旧runner未注册回调，复现DEVICE_ERROR断言失败。真实LVGL测试先因缺maze_ui_set_trial_service接口编译失败；补实现后通过。
- `model-runner.log`：原模型/状态/导航/成绩、地图/镜头及runner三模式通过。分块显示总开销128ms另加服务让出时间，控制持续推进；单块128ms仍触发-1004；无新采样仍触发-1001。没有改100ms阈值、吞错误或跳过运动。
- `ui-scroll.log`：真实SDK LVGL确认事件多次调用服务，裁剪/固定HUD像素/旧点击/暂停重玩保持；对象数及主机可用堆38528B前后一致，最大刷新122100像素。没有宣称本轮降低像素量或提升目标帧率。
- 字体160字形再现不变；构建脚本6测试通过。独立只读复核无阻塞缺陷，事件文字歧义已按实际SDK改为“提交回调返回后”。

单条带若本身阻塞超过100ms，仍可能报错，这是保留的真实故障检测。实际条带耗时/滚动流畅度与原路径修复效果需目标板复测；TC-052仍未通过，不恢复B/C，无自动烧录/提交推送。

最终补充：runner-final.log明确列出sliced/unchunked/starved/recovery四模式；recovery先注入真实-1004，再执行重试校准、继续并保持分块服务正常。正式UI当前源码重新编译及正常/错误页回归见ui-normal.log和ui-error.log。修复试验完整SDK构建与目标符号/哈希见[构建](../../builds/2026-11-02-scroll-service-01/README.md)，原板端失败尚待复测消除。
